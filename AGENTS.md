# tag.bet — заметки для агентов

- Сайт на Next.js 16 (App Router, previous caching model — без `cacheComponents`), Tailwind v4, TypeScript 7.
- Все данные — через `lib/data.ts` (кэш `lib/cache.ts` + лимитер `lib/rate-limit.ts`). Не вызывайте `apiGet` из страниц напрямую: у SStats лимит 30 запросов/мин без ключа.
- Страницы с данными — `dynamic = 'force-dynamic'`; кэширует наш слой данных, а не Next.
- У динамических страниц нет `loading.tsx` намеренно: иначе `notFound()`/`permanentRedirect()` отдают 200 вместо 404/308.
- Цветовой токен фона называется `ink` (не `base`: в Tailwind v4 `text-base` — размер шрифта).
- Партнёрские ссылки — только через `goHref()` → `/go/[slug]` (учёт кликов + subid) и `CtaLink` (rel=sponsored).
- Тексты — по-русски; названия команд в текстах только в именительном падеже («команда «X»»).
- Демо без сети: `SSTATS_MOCK=1` (полосы над шапкой нет — только строка в подвале, `IS_MOCK` в `Footer.tsx`). Часы в демо стоят (всегда 4 октября 2026-го, 19:30 МСК; `SSTATS_MOCK=design` — то же самое): один и тот же день во всех состояниях, прогрев разбирает все матчи топ-лиг (и идущие — для графика «Форма»); так попросил владелец, пока идёт работа над виджетами. `SSTATS_MOCK_NOW` «переводит» часы демо — дальше время идёт. Часы сайта — только `appNow()` из `lib/format.ts` (их же берёт демо), не `Date.now()` там, где речь о времени матчей. Кэш демо на диск не пишется (`lib/cache.ts`), иначе старые данные без эмблем живут часами. Эмблемы в демо — `.data/team-logos.json` от `npm run team-logos` (`scripts/team-logos.mjs`: команды демо-лиг из `/Teams/list` по странам, ~11 запросов; читает `lib/sstats/team-logos.ts`, файл перечитывается при изменении); без файла — монограммы и подсказка в подвале. Проверки: `npm run typecheck`, `npm test`, `npm run build`.
- «Матч в слайдах» (сторис): данные — `lib/story.ts` → `/api/story/[id]`, просмотр и графики — `components/story/`. Ссылки на матч в списках — через `StoryLink` (обычная ссылка для SEO, клик открывает сторис).
- Кружки историй на главной: группы — `lib/story-groups.ts` (порядок по `lib/rank.ts`), ряд — `components/story/StoryCircles.tsx`, очередь передаётся в просмотрщик через `openStory({ queue })`. Просмотренные — в `localStorage` (`components/story/seen.ts`, ключ `tagbet:seen:v2`), только для колец и отдельно для каждого кружка (отметка «кружок:матч»): просмотр в одном кружке не гасит другие, открытия из списков и виджетов не считаются; сегменты гаснут по порядку от верха. Очередь по тапу и отметки повторов — `components/story/queue.ts` (тест `tests/story-queue.test.ts`). На главной — «В игре», «Топ дня» и до 5 главных тегов (`mainCircles`), подписи в одну строку, без решётки и с большой буквы («Кэф упал», «50 на 50» — `storyLabel` в `lib/story-groups.ts`), так же — в шапке просмотрщика; так решил владелец (раньше решётка была у всех кружков). У тегов в строках матчей, на страницах тегов и внутри слайдов решётка остаётся.
- «Сводка дня» (первый экран страницы дня — сегодня, в прошедшие и будущие дни): данные — `lib/day-summary.ts` (`mainMatches`, `dayCounts`, `goalsPicks`, `linePicks`, `moveExample`) и `lib/lines.ts`, вид — `components/DaySummary.tsx` + `components/TopCarousel.tsx` (клиент). Схема — по заданию владельца (сформулировано вместе с ChatGPT): понятный главный матч и разные по назначению способы просмотра — истории (короткий просмотр матчей) и подборки (полные страницы дня со сравнением и фильтрами).
  - «Главные матчи»: до 5 встреч (`mainMatches`: по важности турнира и команд — `prestige`, сначала по одной на лигу; идущие и предстоящие важнее сыгранных, на прошедших днях — итоги; молодёжные, женские, перенесённые — мимо), стрелки «1 из 5» (на телефоне — внизу и свайп), без автопрокрутки; лента со scroll-snap, без JS видны все матчи, высота — по самому высокому слайду. Шапка: слева турнир и тур (красная точка — идёт), справа стрелки и чип дня, в углу сверху и справа поровну. Чип дня — переход на страницу дня («Вчера · Сегодня · Завтра», `dayHref`): выбранный день меняет всю страницу согласованно (блок, подборки, список) и уходит в ссылки подборок; раньше чип менял только блок — владелец передумал.
  - Слева в слайде — эмблемы, полные названия, время («через 40 мин») или счёт у каждой команды и минута LIVE красным, «итог» после матча; ярче — кто ведёт или победил. Сразу под табло — «Разбор за минуту» (на компьютере — подпись в слайде: вся карточка — ссылка на сторис; на телефоне — кнопка под лентой рядом со стрелками). «Выгодно» в блоке больше нет — выгодные ставки в таблице ниже.
  - Справа — одна открытая область без внутренних карточек, по состоянию матча. До начала — строка кэфов одного букмекера «Хозяева · Ничья · Гости» (простые слова вместо «П1/П2») с подписью «Коэффициенты · Фонбет, линия на 19:30» и два факта с выборкой (`lib/facts.ts`: «Хозяева забивали в 9 из 10 последних домашних матчей»; «Фонбет: кэф на победу гостей снизился с 2.40 до 1.97 с открытия линии до 19:30»): факты о командах — из разбора матча (`MatchSummary.facts`, выборка от 5 матчей, личных встреч — от 4), движение линии — того же букмекера, что в строке кэфов; второй факт — от 740px высоты окна. В игре — «Сейчас в матче»: удары в створ и угловые, названия команд над значениями, тонкая полоса долей (минута — только слева под счётом). После матча — «Статистика матча» (удары в створ, угловые, xG — только настоящий из статистики матча, иначе владение; третья строка — от 740px высоты окна) и «Подробности матча →» (ссылка поверх накладки сторис). Вероятностей, полосы шансов, выводов словами и графиков формы в блоке нет: доматчевые вероятности — на странице матча с подписью «До матча», а в игре там же «Сейчас в матче». Нет данных — так и пишем («Статистика по ходу игры пока не пришла»), нулями не заменяем; 0 : 0 из API — настоящее значение (`visibleStats` прячет пустые строки только в списках статистики).
  - LIVE-кэфы не показываем: в SStats они только у Bet365 (зарубежный букмекер). Легальный источник — PARI (`/Pari/odds/history`, `/Pari/events` в API) — отдельным шагом, вместе с настоящей историей линии по времени.
  - «Подборки» (маленькая подпись 13px, `text-mute`, как «Топ-турниры») — три перехода 1:1:2 (`NavTile`), компактные, без крупных цифр: название и подпись, стрелка в углу (сверху и справа поровну), 1–2 строки превью с настоящими количествами; вся плитка — ссылка, высота одна. «Все матчи» («Расписание и результаты»; «31 матч · 6 LIVE», «4 турнира · 10 сыграно» или «первый — в 13:00») → список дня `#matches`; «Голевые матчи» («Полная подборка на 3+ гола»; «3 матча с шансом от 55%», «выше всех: …») → `/matches/[date]/goals`; широкий «Движение коэффициентов» («Изменения линии за день»; пример — матч, исход, «Фонбет, до матча: 7.57 → 6.26», справа `MoveChart` — две точки, под ними период «открытие … 19:30 / начало матча»; упал — янтарь, вырос — серый) → `/matches/[date]/odds`. Нет линии — простые слова («Линия букмекеров ещё загружается», «Заметных изменений линии нет»), без выдуманных цифр. Прежние варианты — плитки из строк текста («стрёмно») и «Цифры дня» с крупными цифрами — владелец заменил этим.
  - Линия одного букмекера (`lib/lines.ts`): все цифры блока и подборок — по одному легальному партнёру (первый из `PARTNERS`, у кого есть нужный рынок; порядок — PARTNERS_ORDER) и одному снимку линии; зарубежных букмекеров по имени не показываем. Снимок — `getOddsSnap` (`/Odds/{id}` и `at` — когда мы взяли линию: своего времени у доматчевых кэфов SStats нет; после начала матча API отдаёт закрытие). Шанс 3+ голов — `goalsLine`: (1/ТБ) / (1/ТБ + 1/ТМ) по паре 2,5 одного букмекера, средние голы команд его не подменяют. Движение — `lineMoves`: открытие → последнее значение по исходам 1X2 и тоталу 2,5, период — `periodText` («с открытия линии до 19:30» / «до начала матча»); кривую между точками не рисуем.
  - Страницы подборок — `app/matches/[date]/goals` и `app/matches/[date]/odds`: шапка с датой и «как считаем», вкладки дня ведут на ту же подборку (`DateTabs section`), фильтры ссылками без JS (`?min=`, `?st=`, `?top=`, `?sort=`; `?dir=`, `?min=`, `?mk=`, `?st=`, `?top=`; значения по умолчанию в адрес не пишем), таблица для сравнения (на телефоне — карточки), отметка охвата (`Coverage`: «линия есть у N из M матчей»). Линия — `daySnaps`: из кэша сразу, топ-турниры без снимка догружаются (страница подборки ждёт ≤2,5 с, страница дня — ≤1,2 с), остальное — в фоне к следующему открытию.
  - «Проверка шансов» с первого экрана ушла: полный график «давали — сбылось» — на `/about#proverka` (`components/ChanceChart.tsx`: столбик — сбылось, белая черта — давали, монохромно, подсказка при наведении/тапе/стрелках; корзины «около 10% … 90%»). Расчёт — `lib/chance-check.ts` (исходы 1X2 сыгранных «взрослых» матчей, шансы — кэфы перед матчем без маржи, итог — по основному времени; корзина меньше 30 исходов не показывается, всего меньше 300 — графика нет), данные — `getChanceCheck` в `lib/data.ts` (30 дней до сегодня; итоги дня кэшируются отдельно и надолго, `/about` ждёт `peekChanceCheck` не дольше 1,5 с, остальное считает прогрев). Не возвращайте виджет «сколько бы заработали» в рублях: крупное «+8 160 ₽, если ставить по 1000 ₽» читается как «ставки — заработок» (ст. 27 закона «О рекламе»), владелец выбрал проценты; и «Фавориты вчера» (кто выиграл, без сравнения с шансом) — тоже нет.
  - Всё тёмное, цвет — только у цифр и выделенной команды: лайм — выгодно, янтарь — кэф упал, красный — live; текст не мельче 13px, без колец-диаграмм (похожи на значок загрузки). Выбор дня у списка «Все матчи дня» (как и чип в блоке, ведёт на страницу дня): `DateTabs` (Вчера · Сегодня · Завтра · дальше день недели без числа; красная точка у «Сегодня», пока идут матчи — `liveToday` из `DayView`) + календарь `DatePicker` (±1 год / +2 месяца), ведут сразу к списку (`#matches`). Сводка должна влезать целиком в 1280×720, 1440×760 и 1470×805 — и в худшем случае (длинные названия в две строки и два факта по две строки), а заголовок «Матчи» — не выглядывать снизу; проверяйте замером. Линии — только там, где разделяют: строки списков и таблиц, выпадающие меню, календарь, подсказки графиков, капсула меню в шапке; переключатели («По турнирам / По времени», «Вид виджетов») — мягкая заливка без рамки. У сводки в видах «Полосы» и «Цифры» рамки свои — пока владелец выбирает вид.
- Цвета по смыслу: лайм — «цена выше честной» (сила перевеса — яркостью лайма, `edgeTone` в `components/Flaps.tsx`), янтарь — прогруз, красный — live. Светофор не используем.
- Для тех, кто не разбирается в цифрах: вывод словами — `lib/verdict.ts` (`buildVerdict`: «Скорее выиграет «X»», голы, падение кэфа, выгодная ставка; `split100` — проценты трёх исходов в сумме ровно 100, `outcomeText`/`outcomeShort` — исход словами вместо «П1»/«ТБ 2.5»). Только факты из данных: про прогруз — «кэф снизился», не «массово ставят». Пороги слов — как у тега #фаворит (60%) и слайда «Кто фаворит» (47%). Без обещаний: только «скорее», «вероятно». В строках и «Матче дня» — только выгодная ставка (обычный прогноз модели бывает «против» вывода). Теги подписаны простыми словами (`label`: `#выгодно`, `#кэф упал`…), slug и адреса прежние; цифра тега — в `TagHit.p`, а не в тексте.
- Обложки кружков историй: плоские, как карточки — заливка `CIRCLE_BG` (= `--color-panel`), тонкая рамка `ring-edge`, светлая иконка тега без теней, бликов и зерна (владелец счёл «стеклянный» вид чужим); кружка «Все теги» нет — в ряду только истории, «Теги» есть в шапке. Иконка тега — `lib/story-art.ts` + `components/story/ArtIcon.tsx` (цвет — только в кольце: лайм не смотрели, красный LIVE, серый просмотрено; цвета тегов `ART` — только для фона просмотрщика). Кольцо (`Ring` в `StoryCircles.tsx`): все сегменты одной толщины 2.5px по радиусу 32, просмотренные — `--color-mute`; не делайте их тоньше или бледнее — кольцо из толстых и тонких дуг владельцу показалось кривым. Фокус с клавиатуры — белый круг вокруг кружка (не рамка вокруг кружка с подписью); у ряда `pt-1.5`, иначе прокрутка ряда срезает этот круг сверху; своя картинка — файл `public/stories/<ключ>.*` (`lib/story-covers.ts`, только сервер). Цифр в кружках нет.
